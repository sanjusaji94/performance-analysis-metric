### Q2: Which of these programs are CPU-bound?

Answer:
To determine whether the programs are CPU-bound, I compared their CPU time (User + System)
with their total real-world runtime (Elapsed).

A program is CPU-bound when the CPU is actively executing code for most of the 
runtime (User time + System time equals the Elapsed), and I/O-bound when it spends much of its time waiting for
external operations (Elapsed is greater than CPU time).

Snippet from transcript_1.txt:
```

System time (seconds): 0.01
Elapsed (wall clock) time: 0:00.32

User time (seconds): 0.40

Elapsed (wall clock) time: 0:00.41
```

Analysis:

Program | User | System | Elapsed | CPU Usage | Conclusion
q1a | 0.31 | 0.01 | 0.32 | ~100% | CPU-bound
q1b | 0.40 | 0.01 | 0.41 | ~100% | CPU-bound
q1c | 0.46 | 0.00 | 0.15 | 297% | CPU-bound (multi-core)
q1d | 0.35 | 0.02 | 0.37 | ~100% | CPU-bound
q1e | 0.34 | 0.02 | 0.36 | ~100% | CPU-bound

Explanation:
All the five programs are CPU-bound because almost the entire elapsed time is spent doing computation on the CPU, with minimal or no waiting for I/O operations.

For q1a,q1b,q1d,and q1e, CPU time(User + System) closely matches Elapsed time -> single-core CPU-bound.

For q1c, total CPU time(0.46 s) is about three times larger than the elapsed (wall-clock time (0.15 s)), giving 297 % CPU utilization. 
This means the program executed in parallel across roughly three CPU cores-still CPU-bound, but multi-threaded.
Multi-core parallel if total CPU time exceeds elapsed time -> (User + System) > Elapsed (CPU % > 100 %)
