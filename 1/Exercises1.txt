### Q2: Which of these programs are CPU-bound?

Answer:
To determine whether the programs are CPU-bound, I compared their CPU time (User + System)
with their total real-world runtime (Elapsed), and the relationship in the "Percent of CPU this job got" value reported by the 'time' tool.

A program is CPU-bound when the CPU is actively executing code for most of the 
runtime (User time + System time equals the Elapsed), and I/O-bound when it spends much of its time waiting for
external operations (Elapsed is greater than CPU time). And in the case of Percent of CPU a program got, a CPU-bound program will 
show a utilization close to 100% or above 100% if it uses multiple cores ,whereas an I/O-bound or idle program will have a much lower CPU percentage.

The relationship between CPU time and elapsed time can also be expressed using the CPU utilization formula:

CPU Utilization (%)= ((User time+System time) / Elapsed time) × 100

A CPU-bound program will have utilization close to 100% (or above 100% if it uses multiple cores),
whereas an I/O-bound program will have a much lower percentage.

### Q5: Which program consumes the most memory?

Answer:

To determine which program consumes the most memory, I examined the "Maximum resident set size(kbytes)" value reported
by /usr/bin/time -v.
This metric represents the peak amount of physical Ram used by a program during its execution - the moment
when the program occupied the most memory in main memory.

It is the most reliable indicator of memory usage, as others reported averages (e.g.,Average shared text size, Average
unshared data size, Average stack size) are usually zero or unrealiable on modern Linux systems.

Therefore, the maximum resident set size (RSS) is used to identify which program consumes the most memory.

### Q7: Which function consumes the most time according to the profile?

Answer:

To determine which function within the program magichex consumes the most CPU time during execution.
A function-level performance profile was generated using GNU 'gprof', which reports
how much total CPU time each function takes and how often it is called.

Commands used:
```
# 1. Compile with profiling enabled
gcc -pg -O /usr/ftp/pub/anton/lvas/effizienz-aufgabe23/magichex.c -o magichex

# 2. Run with required arguments
./magichex 3 0 >/dev/null

# 3. Generate profile report

```
Summary of Tools Used:

1. -pg -> enables function-level profiling and creates gmon.out
2. ./magichex 3 0 -> runs the program with the specified input
3. gmon.out -> Binary log file automatically written at program exit containing timing and call data
4. gprof -> Analyses execution data and lists time spent in each function (reads executable and gmon.out,
   then produces readable performance report)
